# 把知识讲给人听

先把知识弄懂，再用读者能接住的话讲清楚，最后做成图文内容。产物由用户决定，不自动扩成课程、游戏或网站。

## 开始前

读取实际资料、已有内容、用户纠正和认可样板。固定主题、读者已有知识、阅读情境、想理解的关系、载体、语言、页数、风格及不可改项。沿用已作出的决定。可合理推断的缺项注明假设后继续；只有会明显改变结果的缺口才问。

使用 [项目启动单](assets/project-brief.md)。面向一个稳定的读者群，不等于所有项目都用同一年龄、职业或画风。

## 理解与表达

读 [知识与读者表达](references/knowledge-and-language.md)。先分清事实、研究结论、概念模型、启发式和原创情境。每个知识单元保留：读者疑问、对象之间的关系或机制、例子、可作的判断、边界、来源。按独立用途拆分，不按原文段落机械切卡，不为凑数量给同一机制换名字。

优先核对原始论文、原作者和权威机构；记录具体章节或 URL、核验日期和支持的主张。资料不足保留待核实，不用“说得通”代替证据。宣传短句和模型生成文字不能反过来当作知识来源。

先写读者认得出的场景，再解释关系。必要术语保留可查名称，并紧接着说明含义。保留因果、否定、概率、条件与例外。比喻只搬运确实对应的关系；有误读风险时说明边界。

内部可以用结构化字段，成稿应顺着人的阅读节奏展开。不要把“定义、机制、应用、边界”四个小标题机械贴到每页。短篇叙事可以用连续段落、图旁文字和过渡句；不要默认“标题 + 一句定义 + 三点总结”。

## 让画面解释知识

读 [美术与交付](references/art-and-release.md)。确定要画的关系，再选对照、分流、组合、循环、连续旅行或生活小剧场。固定色板、线条、材质、情绪与字体角色，允许镜头、主体大小、留白和图文组织随内容变化。

可从 [暖纸手绘预设](assets/style-preset.json) 开始。它只是一个可替换的美术参数集，不是必须继承的品牌。参考图分别标记 style / identity / composition，固定必要部分，不复制无关角色和道具。

主插画优先使用可用图像模型；准确中文、数字、来源和标签独立排版。程序可以画有意义的辅助线、页码和边框，但不拿机械 SVG 拼图冒充模型插画。工具不可用时完成文字、分镜和 [插画任务单](assets/illustration-brief.md)，如实说明缺少实际图片。

## 成稿与介绍

统一视觉语言，改变版式节奏。不要让所有页面成为相同的几个盒子，也不要强塞吉祥物。确定观看尺寸和字号下限，空间不足先调整句意、版面或图片，不无限缩字。图中标签不够放时移到图外。

若需更细的制版和检查脚本，可另外使用 knowledge-card-art-direction；本 Skill 无强制外部依赖。两页小项目不另加一整页封面。

介绍实际用途、输入和交付物，让人先看真实样页。不能虚构效果、评价、销量、免费承诺或已发布状态。联系方式和交易设置按新项目决定，不从案例继承。发布和对外消息依用户授权处理。

## 看成稿，再交付

分别检查知识来源、读者理解、图文一致性、实际字号、文件可用性。看真正导出的每页图片和 PDF，不能只查源代码。自动几何检查不能替代看图，也不能证明真实读者理解。

交付用户指定成品和可编辑源，保留知识 ID、来源、风格、采用插画、完整提示、排版参数、必要修订与检查结论。输出范围小就合并记录，不制造空文档。不将第三方扫描件、秘密值、私人路径或无权分发的素材装入包。

参见 [太阳系两页案例](references/solar-system-case.md) 与 [安装和验收清单](references/installation.md)。只有实际完成的环节才标完成；人工读者试读、宿主自动发现和外部发布各自需要证据。
